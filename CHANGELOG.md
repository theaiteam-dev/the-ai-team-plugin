### Added

- **Frankie — mission-tail QA/Demo Man agent** (`agents/frankie.md`, #774–#785): New once-per-mission terminal agent that walks a mission's Definition of Done against the running app after all work items reach `done`, before Stockwell's Final Mission Review, producing a versioned evidence bundle. Ported verbatim from a field-tested standalone profile (`prd/ready/010-frankie-profile.md`) per PRD decision 9, wrapped with plugin frontmatter (opus model, observer hooks, skills: `ateam-cli`, `agent-lifecycle`, `teams-messaging`, `a11y`, `perspective-test`). Frankie reads the project's execution contract (surfaces, QA recipe, testing_level, evidence policy) and the mission's DoD, never invents a QA recipe or describes app behavior from memory, and structurally cannot fix code, edit tests, or edit any pre-existing file under `specs/` — he can only write his evidence bundle (`.qa-evidence/<mission>/`) and brand-new FlowSpec flow files. Failures are reported to Hannibal by name with exact repro steps and a failing screenshot; because `done` is terminal (ADR 0005), reopening a failed item is a manual operator action, not an automated bounce.
- **Frankie registered across all five agent registries** (#774): `packages/shared/src/agents.ts` (`VALID_AGENTS`/`AGENT_DISPLAY_NAMES`), the MCP server's Zod schema (via the shared re-export), `scripts/hooks/lib/resolve-agent.js` (`KNOWN_AGENTS`), `packages/kanban-viewer/openapi.yaml`'s `AgentName` enum, and the Go CLI's client-side `validate.Enum` checks in both `agents-start`/`agents-stop` — closing a gap where the CLI rejected `--agent frankie` locally before any HTTP call could run.
- **Execution-contract reader** (`scripts/hooks/lib/qa-contract.js`, #775): Parses and normalizes the new execution-contract block (`surfaces`, `qa.seed`, `qa.account.credential_env`, `qa.drive`, `testing_level`, `evidence`, `review_tier`) out of `ateam.config.json`, returning a fully-defaulted object even when the config is missing, partial, or malformed. Exposes `canFrankieDrive(surfaces)`, deliberately narrow today (only `web` is drivable — FlowSpec's `cli`/`api`/hardware adapters are roadmap issues), so the mission-completion gate stays inert on non-drivable repos instead of deadlocking them.
- **`/ai-team:setup` writes the execution contract** (`commands/setup.md`, #779): Setup now detects thin pointers (surfaces, seed script, credential env-var name) from the repo and confirms them, and asks four genuine policy questions (QA driver, testing level, evidence policy, review tier) via `AskUserQuestion`, writing the result into `ateam.config.json` in the shape `qa-contract.js` expects. Never proposes a credential value, only its name.
- **Frankie write-guard hook** (`scripts/hooks/block-frankie-writes.js`, #780): PreToolUse hook structurally enforcing Frankie's hard rules — blocks all edits to implementation/test files and to any pre-existing file under `specs/`, while allowing his evidence bundle and brand-new flow files to write freely. A **CRITICAL path-traversal vulnerability** (a crafted path like `specs/../src/x.ts` could escape the allowlist) was found during review and fixed by anchoring the traversal check (`hasTraversalSegment()`, exact `..` path-segment match) at the single choke point guarding both the `specs/` and `.qa-evidence/` allowlists. Verified independently by Lynch, Amy, and Stockwell, who each probed the live hook directly rather than trusting the tests.
- **Mission-tail wiring: Frankie runs before Stockwell** (`playbooks/orchestration-native.md`, `playbooks/orchestration-legacy.md`, `commands/run.md`, `agents/hannibal.md`, `CLAUDE.md`, `README.md`, `docs/ORCHESTRATION.md`, #781): Once every item reaches `done`, the orchestrator dispatches a fresh, non-pre-warmed Frankie before Stockwell's Final Mission Review, so Stockwell's review always includes Frankie's evidence bundle and graduated specs (ADR 0004). A Stockwell rejection restarts the tail at Frankie, not post-checks, once the named items are back in `done`.
- **Tawnia stages Frankie's evidence bundle** (`agents/tawnia.md`, #782): The final commit now recognizes `.qa-evidence/<mission>/` and newly-created `specs/*.flow.yaml` files as mission-attributable output (not unattributable dirty state) and stages them alongside item outputs and docs; the PR body links Frankie's report. The drivable-surface exemption threads through so non-drivable repos are unaffected.
- **Mission-completion gate for Frankie's evidence** (`scripts/hooks/lib/stop-gates.js`, `scripts/hooks/enforce-final-review.js`, `scripts/hooks/enforce-orchestrator-stop.js`, #783): Extends Hannibal's existing final-review Stop gate so a mission on a repo with a drivable surface cannot finish until Frankie's evidence bundle exists — mandatory like Amy's probing and Tawnia's commit, held by a hook rather than by prose. Repos with no drivable surface (`canFrankieDrive() === false`) are exempt. The gate lives in the shared `lib/stop-gates.js` and is enforced by **both** of Hannibal's Stop hooks: `enforce-final-review.js` binds only for subagent sessions via agent frontmatter, while `enforce-orchestrator-stop.js` is the one registered plugin-wide and therefore the one that fires in the primary execution mode, where Hannibal runs in the main session. An operator who cannot run Frankie (no Playwright headless shell, no flowspec, dev server unavailable) can override with `ATEAM_SKIP_FRANKIE_GATE=1`, which the block message names.
- **Face authors the mission's Definition of Done on the first pass** (`agents/face.md`, #776): Appends a `## Definition of Done` section (10-15 user-visible statements) directly beneath the executive summary before Sosa's review runs, so the DoD rides the existing human-blessing gate at Sosa instead of adding a new interruption point. Fills `write-prd`'s blank DoD scaffold in place when present (avoiding a duplicate heading), inserts fresh for legacy PRDs, and revises in place on the second pass per Sosa's findings — failing closed (reports a bug, never silently recreates) if the section can't be located. Acceptance criteria on user-facing items must now be written as user-visible sentences, not implementation-side assertions.
- **Sosa's drivability standard** (`agents/sosa.md` §14, #777): Flags any DoD statement or user-facing acceptance criterion that can't be verified by running the project's contract commands in a fresh checkout — not user-visible, no reachable path, missing QA recipe, or crossing an external boundary the dev environment can't answer — as a rejection or open question before build, prescribing the fix as a Wave-0 work item rather than orchestration config. Reproduces the mission DoD verbatim in the refinement report for the human blessing gate.
- **Face's Project Readiness Audit gains a QA-contract check** (`agents/face.md`, #785): A mission with user-facing work on a drivable repo that has no QA recipe now produces a Wave-0 "Establish QA contract" scaffolding item, closing the gap before Frankie ever needs to walk it.
- **Documentation pass across the plugin's roster, pipeline, and hook references** (#784): `CLAUDE.md`, `agents/AGENTS.md`, `docs/ORCHESTRATION.md`, `docs/PLUGIN-DEV.md`, `README.md`, and three skill files now consistently describe Frankie's roster entry, his position between "all items done" and Stockwell in the mission tail, his boundaries, and his hook wiring — replacing stale eight/nine-agent references and a stale "Lynch performs Final Mission Review" mention.
- **ADRs 0004-0006:** `adr/0004-frankie-before-stockwell-in-mission-tail.md` (Frankie runs before Stockwell; a Stockwell rejection restarts the tail at Frankie); `adr/0005-done-is-terminal-no-in-mission-rework.md` (Frankie ships without a bounce — all four API paths out of `done` are verified closed; reopening a `done` item is a manual operator action); `adr/0006-ateam-config-schema-deferred.md` (the `ateam.config.json` whole-config schema stays deferred; `commands/setup.md` becomes the one canonical template, `qa-contract.js` is the executable definition of the execution-contract fields only).

### Fixed

- **Hannibal's Stop hooks queried API routes that never existed — all mission-completion enforcement was inert** (`scripts/hooks/lib/stop-gates.js`, `scripts/hooks/enforce-final-review.js`, `scripts/hooks/enforce-orchestrator-stop.js`): Both hooks built URLs like `${apiUrl}/api/projects/${projectId}/board` and `${apiUrl}/api/projects/${projectId}/missions/current`. The API is flat and keyed by the `X-Project-ID` header the hooks already send — `/api/board` and `/api/missions/current` — so every real invocation 404'd and the fail-open branch silently allowed the stop. The test suites never caught it because they inject `__TEST_MOCK_BOARD__`/`__TEST_MOCK_MISSION__` and skip the fetch path entirely. Beyond the URLs, the hooks also parsed a `columns` map the API has never returned (it returns a flat `items[]` list keyed by `stageId`, inside a `{ success, data }` envelope), never asked for `includeCompleted=true` (so the done count could only ever be 0), and read `final_review_verdict`/`postcheck.passed` fields the mission payload does not carry (the real signals are the mission's `finalReview` report and its `completed` state). Fetching, URL construction, and response normalization now live in `lib/stop-gates.js`, shared by both hooks, and are covered by an integration suite that drives the hooks against a stub HTTP server serving the real response envelopes — so route or shape drift fails the build instead of silently disabling enforcement.
- **Headless (print-mode) teams gaps — four fixes from validation mission `M-20260719-002`** (the first fully-headless pipeline run; docs/spikes/2026-07-13-teams-mode-headless.md):
  - **Orchestrator address is `main` headless, not `team-lead`.** In `claude -p` sessions, `SendMessage` accepts only teammate names or the literal `main`; sends to `team-lead` error as invalid. The playbook, spawn-prompt templates, and `teams-messaging`/`pool-handoff`/`agent-lifecycle` skills now carry the self-healing rule: try `team-lead`, and on an invalid-address error switch to `main`. (The probe's orchestrator discovered and worked around this unprompted mid-mission.)
  - **New "Headless (Print-Mode) Operation" playbook section:** a `-p` lead that ends a turn with only text terminates the session — killing running teammates mid-work and stranding the mission (this killed leg 1 of the probe with an item mid-probe). The playbook now mandates holding the turn with a bounded poll (`sleep` + board re-check) while any teammate is working, and documents the validated recovery (re-run `/ai-team:run`; release stale `.busy` claims; re-dispatch).
  - **`handoff-start`/`handoff-stop` events now actually land.** The API's `eventType` enum rejected them (400) since the latency instrumentation shipped, and the emitters sent a shape the route couldn't store anyway (missing `status`/`summary`/ISO `timestamp`; top-level `itemId` was dropped). Both fixed: enum extended, emitters send route-conformant events with the pairing `itemId` inside `payload`. Surfaced by the observer failure log during the probe — 10 dropped events, loudly recorded.
  - **Backward peer messages (ACK / REJECTED / TEST BUG) now address by agentId.** Forward handoffs use `claimedNextAgentId`, but backward hops have no auto-claim — name-addressed ACKs silently dropped headless (senders burned their 20s timeout every handoff). Skills now resolve the target's agentId by reading its pool marker content (read-only `cat` of `<instance>.idle|.busy` — the same id `mark-idle --agent-id` recorded), falling back to the name only when the marker is empty (interactive mode).
- **Observer telemetry attribution — four related fixes** (root-caused after overnight mission `M-20260714-001` completed green with ZERO telemetry):
  - **Token-usage POSTs now carry CF-Access headers.** The v1.9.0 CF-Access fix patched `sendObserverEvent` but missed the two inline `/api/hooks/token-usage` fetches in `observe-stop.js` / `observe-subagent.js` — behind Cloudflare Access every per-message token POST 302'd and was silently swallowed, leaving `MessageTokenUsage` (and therefore `MissionTokenUsage` / all cost reporting) empty in prod. The POST is now centralized as `sendTokenUsage()` in `lib/observer.js` (like `apiEventHeaders`) so the sibling call sites can never drift on headers again.
  - **Observer preflight (`scripts/hooks/observer-preflight.js`).** Telemetry depends on env vars in the HOOK process env, which is not the env Bash tool calls see (Bash shells source the user profile; hooks inherit only the harness env) — so a mission can run perfectly while every observer POST silently dies. A new SessionStart hook records what the real hook env can see (project id, CF creds, live API probe) to a status file and warns in-context when a mission-shaped env is broken; `observer-preflight.js --check` (wired into the `/ai-team:run` precheck) reads that file and fails loudly — including when the status file is missing entirely, which means hooks aren't firing at all.
  - **Unattributable sessions no longer post.** `sendObserverEvent`, `sendTokenUsage`, and `sendDeniedEvent` now skip entirely when `ATEAM_PROJECT_ID` is unset, instead of falling back to `projectId='default'` — which had every unrelated Claude session on a machine with the plugin spamming prod with `default`/`hannibal` events (and camouflaging real attribution failures).
  - **Bounded mission attribution (`lib/mission-attach.ts`).** `/api/hooks/events` and `/api/hooks/token-usage` attached events to the newest un-archived mission with no state filter, so a completed-but-unarchived mission absorbed all later sessions in the project indefinitely (prod: 07-14 sessions attributed to a mission completed 07-01). Active missions still receive events; completed/failed missions only within a grace window after completion (default 60 min, `ATEAM_MISSION_ATTACH_GRACE_MINUTES` override), anchored on `startedAt` when a failure path never stamped `completedAt`; outside the window events store with `missionId: null`.

### Added

- **agentId-addressed pipeline handoffs (`pool mark-idle --agent-id` → `claimedNextAgentId`):** peer-to-peer handoffs (Murdock→B.A.→Lynch→Amy) now address the next agent by its harness `agentId` instead of the friendly instance name. A headless-mode spike (`docs/spikes/2026-07-13-teams-mode-headless.md`) proved that under `claude -p` a teammate cannot resolve another teammate's spawn-name — a name-addressed `SendMessage(to: "ba-2")` is accepted by the sender but silently dropped — while an agentId always delivers (and wakes the idle instance to receive it). Since an agent cannot discover its own agentId, the orchestrator (which holds each id from the `Agent` spawn return) records it: `ateam pool mark-idle <instance> --agent-id <id>` writes the id as the marker file's content; `agentStop`'s pool auto-claim reads it back and returns `data.claimedNextAgentId` alongside `claimedNext`; the `pool-handoff` / `teams-messaging` / `agent-lifecycle` / `ateam-cli` skills and the native playbook address the START to the agentId, falling back to the name only when no id was recorded. Backward-compatible: omitting `--agent-id` leaves the marker empty and preserves name-only handoff. Backward/rejection routing still addresses by name (documented follow-up). Requires CLI ≥ 1.10.0 (`minCliVersion` bumped).
- **`/ai-team:sweep` one-shot post-mission review → capture → autofix** (`commands/sweep.md`): automates the operator habit of running a branch-vs-`main` code review after every mission and hand-filing the findings. Runs the new `ai-team:code-review` skill, captures Must Fix / Should Fix findings as `RetroLearning` rows (`--source code-review`, severity mapped must→high/critical, should→medium; Consider items reported but never captured or auto-fixed), then fans out fix subagents per the review's Parallelism Estimate — TDD-first, never weakening tests — and lands one `fix(...)` commit referencing the learning row IDs. Zero-finding sweeps are valid outcomes (no quota); autofix requires a clean working tree so it never mixes into operator WIP. Motivated by mission `M-20260702-001`, where Stockwell approved and the manual post-mission review still found three real bugs (RetroLearning rows 5–7); the mission-learning-loop PRD §5 is amended accordingly. Operator-initiated only — auto-dispatch from `/ai-team:run` is deferred until the one-shot earns trust.
- **`ai-team:code-review` skill** (`skills/code-review/`): ported from the operator's personal skill. Branch-aware scope detection (committed vs uncommitted, feature vs base branch), a ten-point review checklist backed by six reference files (api-and-data, code-quality, infrastructure, security, testing, type-safety), Must Fix / Should Fix / Consider severity triage, and a Parallelism Estimate that groups findings into independent-file fix agents — which `/ai-team:sweep` uses directly as its autofix dispatch plan. Its must/should/consider vocabulary is the origin of PRD §8's severity terms; the sweep's capture step now defines the canonical mapping onto `RetroLearning`'s low/medium/high/critical, resolving the vocabulary mismatch flagged in Stockwell's M-20260702-001 final review.
- **Severity enum validation on `POST /api/learnings`:** the API now rejects severities outside `low | medium | high | critical` with a 400 (previously any non-empty string was stored silently, so a typo like `hihg` would never match rank/tuning vocabulary). Mirrors the activity route's `VALID_LEVELS` pattern; the corpus backfill script already emits only valid values, so nothing existing breaks.
- **Architecture Decision Record (ADR) baking into planning pass:** Face and Sosa now collaborate on identifying architectural decisions during PRD decomposition. Sosa reviews work items and flags decisions that set precedent for future missions — genuine architecture/technical-approach trade-offs, scope boundaries with lasting rationale, human answers to ambiguities that establish conventions, and pattern decisions that should recur. Face then records these as `adr/NNNN-<title>.md` files following a standard template (Accepted status, decision context, alternatives considered, consequences for future missions). When Sosa's report has no ADR candidates, Face skips ADR recording entirely — zero-ADR debriefs are valid and expected. This bakes architectural memory into the codebase at decision time rather than leaving it in chat transcripts or markdown graveyards. ADR recording is done as part of Face's second pass (refinement) after Sosa's critique and human questions are resolved.
- **Mission Learning Loop comprehensive PRD (Phase 1–3):** New `prd/drafts/mission-learning-loop.md` specifies a three-phase initiative for systematic capture and improvement of A(i)-Team execution. Phase 1 (capture & rank, already shipped) creates structured `RetroLearning` records from mission debriefs, matches learnings to a curated fingerprint corpus, and surfaces recurrence-ranked patterns via `ateam learnings rank`. Phase 2 (tuning rounds, planned) adds `TuningProposal` and operator-driven verb walk (accept/edit/merge/demote/reject/defer) with durable dismissals that resurface on new evidence. Phase 3 (eval gate, planned) integrates `skill-eval` to verify proposed changes against fixtures before ship, with explicit tracking of `shipped-unverified` status where fixtures don't exist. Includes altitude escalation on recurrence (skill → prompt → hook), cross-project promotion signals, and edge-case handling for review inputs unavailable, eval diagnosis gaps, and demote/reject reversals. Validation plan targets backfill of existing corpus, end-to-end debrief, and single-skill tuning round.
- **Accurate per-message token attribution:** End-to-end tracking of token usage at the individual message level, replacing the prior per-transcript summation. New `MessageTokenUsage` Prisma model stores agentName, model, and token counts (inputTokens, outputTokens, cacheCreationTokens, cacheReadTokens) uniquely keyed by `messageId` (id-less messages use a synthetic `${sessionId}:idx:N` key). Observer hooks (`observe-stop.js`, `observe-subagent.js`) now parse transcripts and emit a fire-and-forget `POST /api/hooks/token-usage` for each message with full validation including agentName — with a scalar bridge for legacy HookEvent telemetry. Messages whose transcript entry carries no model are attributed to `unknown` rather than dropped, so cost is never silently lost. Mission token-usage aggregation now runs in `POST /api/missions/{id}/token-usage`, which SUMs MessageTokenUsage rows grouped by (baseAgentName, model) and upserts MissionTokenUsage; the companion `GET` returns the cached rows. This eliminates the prior HookEvent path and its deduplication logic. Token cost calculation and UI display remain unchanged; the foundation is now per-message granular.
- **TokenUsagePanel dual-view:** Token usage display now supports two views: (1) per-agent rollup showing total cost per agent with proportional bars, (2) per-model breakdown showing cost breakdown by Opus/Sonnet/Haiku within each agent. Toggle via "View" button in the panel. Full a11y support with keyboard navigation (arrow keys, Enter), ARIA labels, and focus management. Model-drift badge highlights agents with heterogeneous model usage (mixed Opus + Sonnet, etc.).
- **Hannibal heartbeat health check:** Hannibal now arms a self-wake every 1500s (25 min, inside the 5-minute Anthropic prompt-cache TTL × 5 windows) via the `ScheduleWakeup` primitive with prompt `"/ai-team:healthcheck"`. The wake fires the new `/ai-team:healthcheck` slash command (`commands/healthcheck.md`), which deterministically re-arms the next wake, pulls `GET /api/missions/current/health-report`, inspects the local `/tmp/.ateam-pool/${ATEAM_MISSION_ID}/` directory, and either pings stalled agents or re-dispatches. Designed to detect silent stalls where a teammate finishes and goes idle without successfully handing off — the wake is bounded so a hung Hannibal can't sit on a dead mission indefinitely.
- **`GET /api/missions/current/health-report` endpoint** (kanban-viewer): pure data-layer endpoint returning per-in-flight-item activity timestamps (`claimedAt`, `lastActivityAt`, `lastActivitySource`, `idleSeconds`, `lastWorkLogEntry`, `recentActivity`) plus an aggregate `missionIdle` boolean (true when every in-flight item has `idleSeconds > 600`). Scoped to the active mission via the `MissionItem` join and a `state notIn (completed/failed/archived)` predicate so it never returns stale data from old missions in the same project. Fallback signal attribution is bounded by `timestamp >= claimedAt` so events from earlier claims on other items don't leak into the current item's view.
- **`ateam missions-health getHealthReport` CLI:** Go wrapper for the new endpoint. Used by Hannibal's heartbeat slash command and available for ad-hoc inspection.
- **Configurable rejection cap (`ATEAM_REJECTION_CAP`):** The default rejection-to-blocked threshold (4) is now overridable per API server via the `ATEAM_REJECTION_CAP` environment variable. Validated as a positive integer at request time; non-integers (`1.5`), `NaN`, zero, and negatives all silently fall back to the default rather than blocking items earlier than configured. Surfaced in the kanban-viewer `agents/stop` route's `getRejectionEscalationThreshold()`.
- **Skill activation telemetry + tool-call histogram + skill-usage endpoints:** Observer hooks now extract `skill_name` and a 12-char SHA-256 `args_hash` for every `Skill` tool call into `HookEvent.payload`. Two new aggregation endpoints expose the data: `GET /api/missions/{id}/tool-histogram` (per-agent tool counts, Prisma `groupBy + _count`) and `GET /api/missions/{id}/skill-usage` (per-agent skill invocations with `invocations` + `distinctArgs` counts; filters `eventType: 'pre_tool_use'` to avoid double-counting pre+post Skill events). Go CLI: `ateam missions getToolHistogram <missionId>` and `ateam missions getSkillUsage <missionId>`. The retro agent renders both as new "Tool Usage" and "Skill Activations" sections.
- **`ScheduleWakeup` payload capture in observer:** Hook events for `ScheduleWakeup` now record `prompt` (truncated to 1000 chars), `reason`, and `delay_seconds` in `HookEvent.payload` and surface the prompt in the activity-feed `summary`. Heartbeat debugging needs to know what each wake scheduled — without this we could only see WHEN wakes fired, not WHAT they asked the next session to do.
- **`ateam pool` CLI subcommands** (`init`, `destroy`, `status`, `claim`, `release`, `mark-idle`): managed pool-lifecycle verbs that replace ad-hoc `ls`/`mv` access to `/tmp/.ateam-pool/<missionId>/`. Atomic claim via `os.Rename`; status returns JSON `{idle: [...], busy: [...], byType: {...}}`; release is `defer`-safe so it runs even on API errors. Hardened in `85a69b2` with stable exit codes, input validation, and the atomic claim path; pipeline agents and the lazy lane pre-warm flow both go through these verbs exclusively.
- **Lazy lane pre-warming via `ateam pool`:** Native-teams orchestration now spawns lane 1 only at mission start, and spawns additional lanes (2..N) on demand when Phase 3 detects no idle Murdock and the next lane number hasn't already failed. Mirrors the lane-failure recovery path so failed lanes are skipped instead of retried each tick. Mission BLOCKED escalation when every lane in `1..N` has failed and items remain in `ready`. Lane readiness is gated on actual `READY:` messages — `.idle` files are created only after each spawned agent confirms alive, preventing the black-hole bug where peers route work into half-spawned sessions.
- **B.A. self-rejection (TEST BUG path) → Murdock:** B.A. may now self-reject with `--outcome rejected --return-to testing` and a `TEST BUG:` summary prefix when the test it was given doesn't compile, throws on valid input, or asserts impossible behavior. The handoff hook restricts B.A.'s rejection to `testing` only. Closes the prior "B.A. blocks waiting for someone to fix the test" stall pattern; the rework still routes through Murdock so the TDD invariant ("every defect becomes a failing test before code changes") holds.
- **Earliest-flagged-stage rejection routing for Lynch and Amy:** Lynch and Amy can route rejections to either `testing` (Murdock) or `implementing` (B.A.) based on which stage their finding implicates earliest in the pipeline (`testing < implementing < review < probing`). Rejections that name a test gap (alone or with an impl bug) go to `testing`; rejections that name only an impl bug go to `implementing`. Closes the loop in one cycle: Murdock writes the failing test → B.A. fills impl in pass-through → Lynch reviews → Amy verifies. `enforce-handoff.js` validates the target via `REJECTION_TARGETS` and blocks misrouted peer handoffs at hook time. Motivation: mission `M-20260417-001` (`WI-242` double-rejection loop) where Lynch routed straight to B.A. without a failing test capturing the defect.
- **Murdock rework mode (Step 2.5):** Triggered when an item arrives in `testing` with `rejectionCount > 0`. Murdock audits whether the rejection points at a real test gap. Two exits: (a) tighten the test until it goes red, then START B.A.; (b) pass-through — tests already cover it, summarize the rejector's verdict and forward to B.A. without touching tests. Carried by a new `rework pass-through START` format in the `teams-messaging` skill that includes the rejector's verbatim rejection plus Murdock's audit verdict.
- **State-shape contract for shared-file splits:** `skills/work-breakdown/SKILL.md` now requires that the FIRST work item in a shared-file chain (sequential dependencies or `parallel_group` co-grouping) pin the full state-shape contract in its acceptance criteria — discriminated UI-mode union, full reducer state + action union, or full method surface — with placeholder branches for unimplemented modes. Subsequent items extend the existing state, never invent parallel state. Surfaced from mission `M-20260506-001` (React Todo Client) where three items split TodoItem.tsx behaviors and each invented its own boolean state, producing 8 boolean slices that allowed impossible combined states (e.g., `isEditing && isConfirmingDelete`) and ~30% test bloat defending against them. Sosa is instructed to flag CRITICAL when a shared-file chain's first-item ACs do not pin the state contract.
- **Slash-command Step 0 invocation across agents:** All pipeline agents (Murdock, B.A., Lynch, Amy) plus Stockwell now load their required skills via explicit `Skill(...)` calls in Step 0 of their prompt, instead of relying on inline procedure hints. This removes ambiguity about whether a skill body is in context — a freeform "follow X" pointer was easy to skim past. Frontmatter `skills:` declarations are reconciled to match Step 0 invocations exactly.
- **Pi (Pi-mono / `badlogic/pi-mono`) coding-agent portability research:** New `docs/pi-coding-agent-portability.md` documenting how A(i)-Team agent files load on the Pi harness as well as Claude Code, what behaviors are equivalent vs. gap-bridged (frontmatter/hooks/permissionMode/per-agent skills), and what work remains to reach functional parity (hook bridge extension, dispatch adapter in playbooks, command adapters, Pi packaging).

Drafts only — neither is built yet.

- **Pipeline parallelism with multi-instance agents:** Runnable pool architecture enabling multiple concurrent instances of the same agent (e.g., `murdock-1`, `murdock-2`, `ba-1`, `ba-2`). Native teams orchestration dispatches work items to available pool members, allowing true parallel feature development within memory and dependency constraints. See `playbooks/orchestration-native.md` for pool-based handoff protocol (#037-047).
- **Atomic pool-based peer-to-peer handoffs:** `ateam agents-stop agentStop` now manages a `/tmp/.ateam-pool/<missionId>/` directory of `.idle`/`.busy` marker files. ### Added — PRD-008: Token Usage Tracking

End-to-end token usage tracking from agent transcripts to dashboard display.
Hooks parse JSONL transcripts to extract token counts on agent stop events. HookEvent
API stores token fields (inputTokens, outputTokens, cacheCreationTokens, cacheReadTokens,
model). Token cost calculator computes estimated USD from configurable per-model pricing.
Aggregation endpoint groups token usage by agent+model for a mission with deduplication logic.
SSE integration emits mission-token-usage events to the dashboard on mission completion.
TokenUsagePanel React component displays per-agent cost breakdown with proportional bars.
Token summary formatter produces one-line commit summaries for CHANGELOG entries.
