235:The draft PR is meant to be squash-merged. GitHub builds the squash commit message from the setting "Default commit message" under Settings, General, Pull Requests. Set it to **Pull request title and description**. With that setting the body of the PR description is the commit message. That description is the file `ateam missions-pr describe` writes (`.qa-evidence/<missionId>/pr-description.md`), and it carries the `Mission:` and `PRD:` trailers. With the other choices (default message, or the commit messages list) the trailers can be dropped or mangled on `main`.
239:GitHub also appends `Co-authored-by` lines to a squash commit. Where they land decides whether `Mission:` and `PRD:` stay readable as trailers. In a sandbox (not confirmed against GitHub), `git interpret-trailers --parse` kept `Mission:` and `PRD:` when the co-author lines sat directly under them. It dropped both when the co-author lines formed a separate paragraph or came after a `---------` separator line. Verify the first real squash merge by running `git interpret-trailers --parse` on the resulting commit on `main` and confirming `Mission:` and `PRD:` appear in the output.
